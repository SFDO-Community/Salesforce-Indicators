# Recommendations for v0.5.1 (collected from the feature-test work)

Product and UX suggestions that came out of the dev-only feature tests. They are **suggestions for the maintainers**, not defects (defects are written up
separately in this folder). Each has the evidence that prompted it.

| # | Recommendation | Why | Evidence |
|---|---|---|---|
| 1 | **Show a message when a mapped card has nothing to show.** If `mappedField` (e.g. `AccountId`) is blank on the current record, the card currently shows only its title, description and a footer chip with the field name, **no indicators and no explanation**. Add a short line such as "No related record: *AccountId* is blank on this record." | An empty card looks like a configuration error to an admin and like a bug to a user. | Contact `Feature Contact Orphan` (FCON-04) with the mapped Account bundle: `shots/badge_FCON-04_RF15.png` |
| 2 | **Make the Key respect the bundle's style.** Pass the page's current indicator style (`avatar` / `badge` / `pill`) into the Key and render each row with the same child component the page uses, so the legend matches. Show the extra values (Badge/Pill Text, inverse text, hover text, action) as secondary detail, not in the swatch. | The Key is style-blind today; badge and pill carry more information than an avatar can show. | `key.js` / `indicatorBundleKey` receive `bundle`, `showRefresh`, `suppressedItemIds` only |
| 3 | **Configuration Manager: a style preview toggle** (button group: avatar / badge / pill). Preview only; it should not write anything. | Admins can see how the same configuration looks per style before choosing one on the page. | Same configuration renders very differently across styles and themes (see the blog draft) |
| 4 | **Mobile: collapse the Key's admin features behind one toggle** instead of removing them; hidden by default on small screens. | The Key is cramped on a phone. | Maintainer observation |
| 5 | **Explain "Show False or Blank" for Badge/Pill.** With no Inverse Badge/Pill Text the false state draws an icon-only chip (working as designed). Add help text on *Show False or Blank* and on the Inverse Badge/Pill Text field, and a line in the Key. A validation rule cannot require it, because the item does not know the bundle's style. | Avatar-only admins should not be forced to enter text; others should be told. | Item `F14_06` on `Feature Blank` |
| 6 | **Offer relative-date literals as a picklist** in the future CMDT creation UI (and validate the literal there). Custom Metadata cannot have triggers, so a typo such as `LAST MONTHS` is accepted today and silently never matches. | Reports and SOQL validate the literal when you save or run; CMDT cannot. | Validation tests `G03`, `G04` |
| 7 | **Document these behaviours:** a merge token on a blank field becomes an **empty string**; tokens on a mapped bundle resolve against the **mapped** record; set background, icon foreground and text colour **together**; the card header icon honours its colours on every theme but an avatar's background is ignored on SLDS2/dark. | Each is observable behaviour an admin will hit. | `findings/blog-advice-styling-indicators.md` |
| 8 | **Level-set `sample_Lead` and `training_Indicators`** for the v0.5 validation rules (images need fallback icons; text extensions need a Match Operator) before the flows that install them are used. | They do not pass the branch's own rules (34 and 23 records rejected). | `findings/shipped-config-fails-validation.md` |
